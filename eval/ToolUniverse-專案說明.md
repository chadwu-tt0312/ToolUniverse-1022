# ToolUniverse 專案說明

本文件旨在詳細說明 ToolUniverse 專案的核心功能、應用場景、技術架構及使用方式，目標是讓大學生程度、但無科學研究背景的讀者也能輕鬆理解。

---

## 1. 本專案用途是什麼? 核心功能是什麼? 實際應用場景是什麼?

### 核心概念
**ToolUniverse** 是一個創新的系統，它扮演著「AI 的工具箱」角色，讓大型語言模型（LLM，例如你可能聽過的 ChatGPT、Gemini）能夠使用真實世界的專業科學研究工具。

想像一下，AI 如果只靠自己腦中的資料（訓練資料）來回答科學問題，就像一個只讀過教科書但從未進過實驗室的學生。ToolUniverse 的出現，就是為了給這個「學生」一套完整的實驗設備和資料庫存取權限。

### 核心功能
1.  **整合超過 600 種科學工具**：這就像一個巨大的工具庫，裡面包含了：
    *   **科學資料庫**：如 `UniProt`（蛋白質資訊）、`ChEMBL`（藥物分子）、`OpenTargets`（疾病與基因關聯）。
    *   **機器學習模型**：用於預測蛋白質結構、藥物效果等。
    *   **文獻系統**：如 `PubMed`，用來搜尋醫學論文。
    *   **臨床資料庫**：如美國食品藥物管理局（FDA）的藥物資訊。

2.  **智慧工具推薦**：當使用者用白話文提出需求（例如：「我想找跟高血壓有關的基因」），ToolUniverse 能幫助 AI 自動從 600 多個工具中挑選出最適合的一個或一組來完成任務。

3.  **簡化工具使用**：它將所有複雜的工具都打包成統一、簡單的格式，讓 AI 可以輕易地呼叫使用，無需為每個工具學習不同的操作方法。

4.  **串聯工具完成複雜任務**：可以像積木一樣，將多個工具串接起來，自動化完成一個複雜的研究流程。

### 實際應用場景
*   **加速藥物開發**：研究人員可以快速找出某個疾病的潛在藥物標靶，搜尋可能的候選藥物，並用 AI 預測藥物的效果與毒性，大幅縮短傳統研發所需的時間與成本。
*   **自動化文獻研究**：研究生或學者可以讓 AI 自動搜尋、閱讀、並總結上百篇論文，快速掌握某一領域的最新進展。
*   **個人化精準醫療**：分析病患的基因資料，預測其對不同藥物的反應，從而推薦最有效的個人化治療方案。

## 2. 本專案的 input/output 分別是什麼?

### Input (輸入)
專案的輸入非常靈活，主要有兩種方式：

1.  **給開發者的直接指令 (Python 程式碼)**：
    研究人員或開發者可以直接在 Python 程式中下指令，明確告知 ToolUniverse 要使用哪個工具以及需要查詢的參數。

    *   **範例**：
        ```python
        # 使用 OpenTargets 工具查詢高血壓 (EFO_0000537) 相關的基因
        result = tu.run({
            "name": "OpenTargets_get_associated_targets_by_disease_efoId",
            "arguments": {"efoId": "EFO_0000537"}
        })
        ```

2.  **給 AI 的自然語言問題 (給一般使用者)**：
    使用者可以直接用口語化的方式向整合了 ToolUniverse 的 AI 應用提問。

    *   **範例**：
        使用者問：「哪些蛋白質和高血壓有關？」
        AI 會在背後自動將這個問題轉化成上述的程式碼指令，去查詢 `OpenTargets` 資料庫。

### Output (輸出)
專案的輸出是結構化的專業資料，而最終呈現給使用者的成果則是經過 AI 解讀和整理後的報告。

1.  **直接輸出 (給開發者/AI)**：
    工具執行後會回傳 `JSON` 格式的原始資料，包含查詢到的數據、分析結果、信賴度分數等。

    *   **範例**：
        查詢高血壓關聯基因後，可能回傳一個包含數十個基因名稱、關聯性分數、參考文獻連結的列表。

2.  **最終產出成果 (給一般使用者)**：
    這些原始資料會再交給 AI 進行處理，最終產出人類易於理解的成果：
    *   **研究報告**：一份完整的分析報告，總結問題的答案、資料來源、分析過程與結論。
    *   **數據視覺化圖表**：例如基因關聯網絡圖、藥物分子 3D 結構圖等，讓結果一目了然。
    *   **決策建議**：基於數據分析，提出具體的建議，例如「基因 A 是個潛力藥物標靶」或「候選藥物 B 的毒性風險較低」。

## 3. 本專案用到那些 LLM ?

ToolUniverse 本身**不是**一個 LLM，而是一個**讓 LLM 變得更強大**的工具系統。它需要與 LLM 結合才能發揮最大作用。LLM 負責「思考和決策」，ToolUniverse 則負責「動手執行」。

它支援市面上幾乎所有主流的 LLM，包含：
*   **商業模型**：OpenAI 的 GPT 系列、Anthropic 的 Claude 系列、Google 的 Gemini 系列。
*   **開源模型**：如 Qwen（阿里）、LLaMA（Meta）等。

### LLM 在專案中的角色：
1.  **工具的「大腦」- 負責理解與推薦**：
    當使用者提出模糊的需求時，LLM 會分析需求，並從 600 多個工具中推薦最合適的。
    *   **範例**：使用者說「找找治療癌症的新藥」，LLM 會推薦 `OpenTargets`（找標靶）、`ChEMBL`（找藥物）等一系列工具。

2.  **研究的「總指揮」- 負責規劃與執行**：
    LLM 會制定一個多步驟的研究計畫，決定使用哪些工具、順序為何，並根據上一步的結果動態調整下一步的行動。
    *   **範例**：LLM 可能會決定：1. 先找疾病關聯基因 -> 2. 分析基因功能 -> 3. 尋找能影響該基因的藥物。

3.  **結果的「翻譯官」- 負責解釋與總結**：
    工具回傳的結果通常是冰冷的數據。LLM 會將這些數據轉化為人類能懂的語言，並生成報告。
    *   **範例**：工具回傳 `{"p_value": 0.001}`，LLM 會解釋成：「這個結果在統計上非常顯著，代表我們的發現極有可能是真實的，而非巧合。」

## 4. 調整配置參數會有哪些影響?

專案的配置參數主要集中在 `.env` 檔案中，用於設定各種外部服務的 API 金鑰 (API Key) 和伺服器位址。這些金鑰就像是讓 ToolUniverse 能夠合法存取各大資料庫和 AI 服務的「通行證」。

| 參數名稱                        | 說明                                                                                             | 影響                                                                                                                              |
| ------------------------------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `OPENAI_API_KEY`                | 用於存取 OpenAI GPT 模型 (例如 GPT-4) 的金鑰。                                                   | **(核心功能)** 如果沒有此金鑰，將無法使用最智能的 `ToolFinderLLM` (AI 推薦工具) 功能，也無法讓 AI 進行複雜的思考、規劃與報告生成。系統會降級使用較基礎的關鍵字搜尋。 |
| `AZURE_OPENAI_API_KEY`          | 如果你是透過微軟 Azure 服務使用 OpenAI 模型，則需要設定此金鑰。                                  | 與 `OPENAI_API_KEY` 作用類似，只是服務提供商不同。兩者至少需要一個才能啟用完整的 AI 功能。                                        |
| `HF_TOKEN`                      | 用於存取 Hugging Face 平台上的模型或資料集。                                                     | 缺少此金鑰，將無法使用託管在 Hugging Face 上的特定機器學習模型工具。                                                              |
| `USPTO_API_KEY`                 | 美國專利及商標局的 API 金鑰。                                                                    | 缺少此金鑰，將無法使用查詢美國專利的相關工具，例如在藥物開發中檢查候選分子是否已有專利。                                      |
| `*_MCP_SERVER_HOST` / `*_URL` | 用於連接外部獨立執行的工具伺服器 (MCP Server) 的位址。例如 `BOLTZ_MCP_SERVER_HOST`。 | 如果你的某些專業工具（如分子對接模型 Boltz）是部署在另外一台伺服器上，這裡就需要設定正確的位址才能讓 ToolUniverse 找到並使用它。 |

**總結**：配置參數的核心是 **API 金鑰**。缺少金鑰會導致對應的**功能降級或直接失效**。特別是 `OPENAI_API_KEY`，它直接影響到專案的「智慧」程度。

## 5. 請提供完整執行過程步驟(根據範例)與系統架構

### 完整執行過程 (以 `demo.py` 範例為例)

以下是一個使用者從提出問題到獲得答案的完整流程：

**步驟 1：載入工具庫**
首先，系統會啟動 `ToolUniverse` 並載入所有可用的 600 多個工具。
```python
from tooluniverse import ToolUniverse
tu = ToolUniverse()
tu.load_tools()
```

**步驟 2：使用者提出需求，AI 進行工具探索**
使用者可能問：「我想研究與『疾病標靶關聯』相關的工具」。AI 會使用 `Tool_Finder_Keyword` 工具來尋找關鍵字相符的工具。
```python
tools = tu.run({
    "name": "Tool_Finder_Keyword",
    "arguments": {"description": "disease target associations"}
})
```
系統會回傳一個列表，裡面是 `OpenTargets`、`ClinVar` 等最相關的工具。

**步驟 3：AI 選擇工具並執行**
根據上一步的結果和對問題的理解，AI 選擇了最適合的 `OpenTargets` 工具，並設定好參數（例如，高血壓的疾病 ID 是 `EFO_0000537`）來執行。
```python
result = tu.run({
    "name": "OpenTargets_get_associated_targets_by_disease_efoId",
    "arguments": {"efoId": "EFO_0000537"},
})
```

**步驟 4：取得並解讀結果**
`OpenTargets` 工具會回傳一個包含數十個基因與蛋白質的 JSON 資料列表。

**步驟 5：AI 生成最終報告**
AI (例如 GPT-4) 會讀取這個 JSON 列表，將其整理、總結，並用通順的語言呈現給使用者，例如：「根據 OpenTargets 資料庫的資料，與高血壓最相關的前三個蛋白質標靶是 A、B 和 C，它們在血管平滑肌中高度表達...」。

### 系統架構
此專案是一個典型的「代理 (Agent)」架構，可以分為三層：

1.  **思考層 (LLM)**：
    *   **角色**：大腦。
    *   **組成**：GPT-4, Claude, Gemini 等大型語言模型。
    *   **職責**：接收使用者需求、制定計畫、選擇工具、解釋結果。

2.  **工具管理層 (ToolUniverse)**：
    *   **角色**：總管/中介。
    *   **組成**：`ToolUniverse` 核心程式庫。
    *   **職責**：管理所有工具的註冊、提供統一的呼叫介面、執行工具並回傳結果。

3.  **執行層 (Tools)**：
    *   **角色**：工廠/實驗室。
    *   **組成**：超過 600 個科學資料庫、API、本地 Python 函數、機器學習模型。
    *   **職責**：執行具體的查詢或計算任務。

## 6. 本專案在公司內部有哪些應用方向?

除了醫藥方向，ToolUniverse 的核心思想——「讓 AI 使用專業工具」，可以應用於任何擁有專業資料庫和分析工具的領域。

### 公司內部應用方向 (製藥/生技)
*   **競爭情報分析**：自動監控競爭對手的專利申請、新藥上市、臨床試驗進展，並生成每日或每週情報摘要。
*   **內部知識庫問答**：整合公司內部的研究報告、實驗數據、會議記錄，建立一個 AI 問答系統，讓員工可以快速找到內部知識。
*   **研究流程自動化**：將標準化的研究流程（例如，新靶點的初步可行性評估）變成一個自動化執行的 AI 工作流，新進人員也能快速上手。

### 其他應用方向
*   **金融領域**：
    *   **應用**：整合 `Bloomberg` API、財報資料庫、股票交易工具。
    *   **範例**：使用者問「幫我分析一下最近科技股的趨勢，並找出 5 支有潛力的股票」，AI 會自動抓取財報、分析新聞、計算技術指標並給出建議。

*   **法律領域**：
    *   **應用**：整合法院判例資料庫、法規資料庫、合約分析工具。
    *   **範例**：律師可以要求 AI「幫我找出所有與『專利侵權』相關的判例，並總結原告勝訴的關鍵因素」。

*   **製造業/工程領域**：
    *   **應用**：整合 CAD 軟體 API、材料性質資料庫、供應鏈管理系統。
    *   **範例**：工程師可以對 AI 說「根據這個設計圖，幫我計算使用鈦合金和碳纖維的成本與結構強度差異」，AI 會自動呼叫模擬軟體並比較結果。

## 7. 如果不依賴現有案例，要自行新增一個案例，建議新增哪個案例?

**建議新增案例：自動化專利檢索與分析**

### 為什麼選擇這個案例？
1.  **價值高**：在藥物開發、材料科學、高科技等任何創新驅動的行業，專利分析都是不可或缺但極其耗時的工作。自動化此流程能創造巨大商業價值。
2.  **可行性高**：ToolUniverse 已經包含了 `USPTO` (美國專利局) 的工具，具備了基礎能力。此案例能很好地展示如何組合現有工具完成複雜任務。
3.  **展示性強**：這個案例能清晰地展示 ToolUniverse 如何串聯「關鍵字搜尋」、「資料提取」、「LLM 總結」等多種能力，是一個絕佳的示範。

### 案例舉例說明
**目標**：評估一個新的抗癌藥物分子 "Molecule-X" 的專利新穎性。

**執行步驟**：
1.  **定義研究計畫 (LLM)**：AI 首先制定計畫：
    a. 搜尋與 "Molecule-X" 結構相似的現有專利。
    b. 搜尋提及 "Molecule-X" 目標靶點（例如 "EGFR"）的相關專利。
    c. 提取這些專利的關鍵資訊（權利要求、發明人、申請日期）。
    d. 總結分析，判斷 "Molecule-X" 的專利風險。

2.  **執行工具 (ToolUniverse)**：
    *   **步驟 a & b**：AI 呼叫 `USPTO_search_patents` 工具，使用化學結構式或關鍵字（如 "EGFR inhibitor"）進行搜尋。
    *   **步驟 c**：針對搜尋到的專利列表，AI 再次呼叫 `USPTO_get_patent_details` 工具，逐一提取每篇專利的詳細內容。

3.  **總結報告 (LLM)**：
    AI 讀取所有提取出的專利資訊，並生成一份總結報告：
    > "關於 Molecule-X 的專利新穎性分析如下：
    > 1.  **結構相似性**：我們發現 3 篇高度相似的專利（專利號 XXX, YYY, ZZZ），主要由 A 公司申請，其保護的核心結構略有不同。
    > 2.  **靶點關聯性**：另有 15 篇專利提及 EGFR 抑制劑，但其化學結構與 Molecule-X 差異較大。
    > 3.  **結論**：Molecule-X 本身可能具有新穎性，但其應用於 EGFR 抑制的思路已有較多佈局。建議進行更詳細的法律分析，並考慮從合成路徑或晶型上建立新的專利壁壘。"

## 8. 針對專案有哪些需要補充說明的部分?

1.  **這不是一個獨立的 APP，而是一個「賦能中台」**：
    使用者不會直接「使用」ToolUniverse。而是會使用**整合了 ToolUniverse** 的應用程式，例如公司內部的研究平台、客製化的 AI 助理等。它的價值在於賦能上層應用。

2.  **結果的準確性依賴於工具本身**：
    ToolUniverse 確保 AI 能「正確地使用工具」，但工具回傳結果的「品質」取決於資料庫本身。如果 `OpenTargets` 資料庫更新延遲，那麼 AI 拿到的也是延遲的資料。AI 的角色是加速和簡化過程，而非創造不存在的資料。

3.  **對操作者的專業知識仍有要求**：
    雖然 AI 降低了技術門檻，但要提出有價值的問題、判斷結果的合理性，仍需要領域專家（如藥物化學家、生物學家）的參與。AI 目前是強大的「副駕駛」，而非能完全獨立作業的「駕駛員」。

4.  **安全與成本考量**：
    使用 ToolUniverse 會頻繁呼叫外部 API（包括 LLM API 和科學資料庫 API），這會產生費用，並且需要妥善管理 API 金鑰以防外洩。在企業內部部署時，成本和安全性是需要規劃的重要環節。
