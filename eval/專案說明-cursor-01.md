# ToolUniverse 專案說明文件

## 1. 專案用途

### 核心概念

**ToolUniverse** 是一個讓 AI 模型（LLM，Large Language Model）能夠使用科學研究工具的系統。簡單來說，它就像是一個「工具庫管理員」，讓 AI 能夠查詢科學資料庫、執行分析、取得研究結果。

### 為什麼需要 ToolUniverse？

想像一下，你問 ChatGPT：「高血壓有哪些相關的蛋白質？」如果沒有 ToolUniverse，AI 只能根據訓練資料給出一般性的回答。但有了 ToolUniverse，AI 可以：

1. **自動選擇合適的工具**：從 600+ 個科學工具中找出能查詢疾病相關蛋白質的工具
2. **實際查詢資料庫**：連接到 OpenTargets 等真實的科學資料庫
3. **取得最新資料**：回傳基於實際資料的準確答案，而不是僅憑記憶回答

### 主要功能

1. **工具整合**：整合超過 600 個科學工具，包括：
   - 科學資料庫（如 UniProt、ChEMBL、OpenTargets）
   - 機器學習模型（如蛋白質結構預測、藥物性質預測）
   - 文獻搜尋系統（如 PubMed、Europe PMC）
   - 臨床資料庫（如 FDA 藥物標籤、臨床試驗資料）

2. **統一介面**：所有工具使用相同的格式，讓 AI 容易理解與使用

3. **智能工具發現**：AI 可以用自然語言描述需求（例如「我想找與癌症相關的基因」），系統會自動推薦合適的工具

4. **工具組合**：可以將多個工具串接起來，完成複雜的研究工作流程

### 實際應用場景

- **藥物發現**：找出疾病相關的蛋白質、搜尋候選藥物、預測藥物性質
- **文獻研究**：自動搜尋相關論文、整理研究證據
- **資料分析**：查詢基因資料、分析蛋白質結構、預測分子性質
- **臨床研究**：查詢藥物資訊、分析臨床試驗結果

## 2. 專案的 Input/Output

### Input（輸入）

#### 方式一：透過 Python 程式碼

使用者可以直接寫 Python 程式碼來使用工具：

```python
from tooluniverse import ToolUniverse

tu = ToolUniverse()
tu.load_tools()  # 載入所有工具

# 使用工具查詢高血壓相關的蛋白質
result = tu.run({
    "name": "OpenTargets_get_associated_targets_by_disease_efoId",
    "arguments": {"efoId": "EFO_0000537"}  # 高血壓的 ID
})
```

#### 方式二：透過 AI 模型（如 ChatGPT、Claude、Gemini）

使用者用自然語言提問，AI 會：
1. 理解使用者的需求
2. 自動選擇合適的工具
3. 呼叫工具取得結果
4. 將結果整理成易懂的回答

例如使用者問：「高血壓有哪些相關的蛋白質？」，AI 會自動使用 OpenTargets 工具查詢並回傳結果。

#### 方式三：透過 MCP（Model Context Protocol）伺服器

ToolUniverse 提供 MCP 伺服器，讓各種 AI 應用程式可以透過標準協議連接並使用工具。

### Output（輸出）

#### 工具執行結果

每個工具執行後會回傳結構化的資料（通常是 JSON 格式），包含：

- **查詢結果**：例如查詢高血壓相關蛋白質，會回傳蛋白質列表、相關性分數等
- **分析結果**：例如預測藥物性質，會回傳預測值、置信度等
- **文獻資料**：例如搜尋論文，會回傳論文標題、摘要、作者等

#### 最終產出成果

1. **研究報告**：整合多個工具結果的分析報告，包含：
   - 研究問題的答案
   - 使用的資料來源
   - 分析過程與結果
   - 結論與建議

2. **資料視覺化**：
   - 圖表（如基因表達圖、藥物性質比較圖）
   - 3D 分子結構圖
   - 網路關係圖

3. **決策建議**：基於資料分析產生的建議，例如：
   - 哪些蛋白質最適合作為藥物標靶
   - 哪些候選藥物最有潛力
   - 需要進一步驗證的方向

4. **工作流程記錄**：完整記錄研究步驟與結果，方便後續追蹤與驗證

### 用途說明

- **加速研究**：自動化資料查詢與分析，節省研究人員時間
- **提高準確性**：使用真實的科學資料庫，而非僅憑 AI 的記憶
- **整合多源資料**：可以同時使用多個資料庫與工具，獲得全面的資訊
- **降低技術門檻**：不需要深入了解每個資料庫的 API，AI 會自動處理

## 3. 專案用到的 LLM

### LLM 在 ToolUniverse 中的角色

ToolUniverse 本身不是 LLM，而是一個「工具管理系統」。它需要與 LLM 結合使用，LLM 負責「思考與決策」，ToolUniverse 負責「執行工具」。

### 支援的 LLM

ToolUniverse 支援多種 LLM，包括：

1. **商業 API 型 LLM**：
   - **OpenAI GPT 系列**（GPT-4、GPT-3.5 等）
   - **Anthropic Claude 系列**（Claude 3、Claude 3.5 等）
   - **Google Gemini 系列**（Gemini Pro、Gemini Ultra 等）
   - **OpenRouter**：可透過單一 API 存取 100+ 種模型

2. **開源 LLM**：
   - **Qwen**（阿里巴巴）
   - **DeepSeek**
   - **LLaMA**（Meta）
   - 其他相容的開源模型

### LLM 在專案中的使用位置

#### 1. 工具發現（Tool Discovery）

**使用位置**：`ToolFinderLLM` 工具

**功能**：當使用者用自然語言描述需求時，LLM 會：
- 理解使用者的意圖
- 分析 600+ 個工具的說明
- 推薦最相關的工具

**範例**：
- 使用者輸入：「我想找與癌症相關的基因」
- LLM 分析後推薦：`OpenTargets_get_associated_targets_by_disease`、`GWAS_search_by_disease` 等工具

#### 2. 工具執行決策（Tool Execution Decision）

**使用位置**：AI 科學家系統（AI Scientist）

**功能**：LLM 會：
- 根據研究問題制定計畫
- 決定需要使用哪些工具
- 決定工具的使用順序
- 根據工具結果調整下一步行動

**範例**：研究高膽固醇血症的藥物發現
1. LLM 決定先查詢疾病相關的蛋白質標靶
2. 根據結果選擇最相關的標靶
3. 查詢該標靶的組織表達資料
4. 搜尋針對該標靶的現有藥物
5. 預測候選藥物的性質

#### 3. 結果解釋與報告生成

**使用位置**：工具輸出處理（Output Hooks）

**功能**：LLM 會：
- 解釋工具執行結果的意義
- 將技術性的資料轉換成易懂的文字
- 生成研究報告
- 提供下一步建議

**範例**：
- 工具回傳：`{"correlation": 0.756, "p_value": 1.23e-15}`
- LLM 解釋：「這兩個基因有強烈的正相關（相關係數 0.756），統計上非常顯著（p < 0.001），表示它們可能共同參與相同的生物功能。」

#### 4. 工具描述優化（Tool Description Optimization）

**使用位置**：工具優化系統

**功能**：使用 LLM 來優化工具的說明文字，讓 AI 更容易理解工具的用途與參數。

### LLM 產生的結果

1. **工具推薦列表**：根據使用者需求推薦的工具清單，包含推薦理由
2. **研究計畫**：多步驟的研究流程規劃
3. **工具參數生成**：根據研究需求自動生成工具所需的參數
4. **結果解釋**：將技術性資料轉換成易懂的文字說明
5. **研究報告**：整合多個工具結果的完整研究報告
6. **下一步建議**：基於當前結果的後續研究方向建議

## 5. 需要補充說明的部分

### 5.1 技術架構補充

#### AI-Tool Interaction Protocol（AI-工具互動協議）

這是 ToolUniverse 的核心技術，類似於 HTTP 協議在網際網路中的角色。它定義了：
- **工具規格格式**：每個工具如何描述自己的功能與參數
- **互動格式**：AI 如何請求工具執行
- **通訊方式**：本地 Python API 與遠端 MCP 協議

這個協議讓 600+ 個不同的工具（資料庫、API、ML 模型）都能用統一的方式被 AI 使用。

#### 工具類型

ToolUniverse 支援多種工具類型：

1. **RESTful API 工具**：連接標準的 REST API
2. **GraphQL 工具**：連接 GraphQL 端點（如 OpenTargets）
3. **本地 Python 工具**：直接在本地執行的 Python 函數
4. **MCP 工具**：透過 Model Context Protocol 連接的遠端工具
5. **Agentic 工具**：使用 LLM 來執行複雜任務的工具

### 5.2 工具生態系統補充

#### 工具分類

ToolUniverse 的工具分為八大類：

1. **ML Models（機器學習模型）**：15 個工具
   - 蛋白質結構預測（AlphaFold、Boltz）
   - 藥物性質預測（ADMET-AI）
   - 分子對接（Boltz2）

2. **AI Agents（AI 代理）**：33 個工具
   - 工具發現器（ToolFinder）
   - 工具組合分析器（ToolCompatibilityAnalyzer）
   - 工作流程規劃器

3. **Software Packages（軟體套件）**：164 個工具
   - 生物資訊分析套件
   - 化學資訊學工具
   - 資料分析工具

4. **Human Expert Feedback（人類專家回饋）**：6 個工具
   - 專家諮詢系統
   - 結果驗證工具

5. **Robotics（機器人）**：1 個工具
   - 實驗室自動化系統

6. **Databases（資料庫）**：84 個工具
   - 基因組資料庫（UniProt、Ensembl）
   - 化學資料庫（PubChem、ChEMBL）
   - 臨床資料庫（FDA、ClinicalTrials.gov）
   - 文獻資料庫（PubMed、Europe PMC）

7. **APIs（應用程式介面）**：多個工具
   - 各種科學資料 API

8. **其他工具**：包含視覺化、資料處理等工具

### 5.3 使用方式補充

#### 整合方式

ToolUniverse 提供多種整合方式：

1. **Python SDK**：直接在 Python 程式中使用
2. **MCP Server**：透過 Model Context Protocol 連接
3. **Web Service**：透過網頁介面使用（[aiscientist.tools](https://aiscientist.tools)）
4. **Claude Desktop**：直接整合到 Claude Desktop 應用程式
5. **Claude Code**：在 Claude Code 環境中使用
6. **Gemini CLI**：在命令列中使用 Google Gemini
7. **其他 AI 平台**：可整合到各種 AI 開發環境

#### 工具發現方式

ToolUniverse 提供三種工具發現方式：

1. **ToolFinderLLM**：使用 LLM 進行語義搜尋（最智能，但需要 API 費用）
2. **Tool_RAG**：使用嵌入模型進行相似度搜尋（快速，需要 GPU）
3. **ToolFinderKeyword**：關鍵字搜尋（最簡單，無需額外資源）

系統會自動選擇最適合的方式，並在需要時降級到更簡單的方法。

### 5.4 擴展性補充

#### 新增工具

ToolUniverse 設計為易於擴展：

1. **本地工具註冊**：使用 `@register_tool` 裝飾器註冊 Python 函數
2. **遠端工具註冊**：透過 JSON 配置檔案註冊遠端 API
3. **MCP 工具註冊**：連接現有的 MCP 伺服器
4. **工具分享**：可以將工具分享到 HuggingFace Spaces

#### 工具優化

ToolUniverse 提供工具描述優化功能：
- 使用 LLM 自動優化工具的說明文字
- 提高 AI 對工具的理解準確度
- 改善工具推薦的品質

### 5.5 安全性與隱私補充

#### API 金鑰管理

- 支援環境變數設定 API 金鑰
- 支援多種 LLM 提供商的 API 金鑰
- 建議使用安全的金鑰管理系統

#### 資料隱私

- 本地工具在本地執行，資料不會外傳
- 遠端工具會連接到外部服務，需注意資料隱私
- 可以選擇僅使用本地工具，避免資料外洩

### 5.6 效能與資源補充

#### 資源需求

- **基本使用**：僅需 Python 環境，無需 GPU
- **進階功能**：
  - Tool_RAG 需要 GPU 來執行嵌入模型
  - 某些 ML 模型工具需要 GPU
  - 大部分工具僅需 CPU 和網路連線

#### 效能優化

- **工具快取**：工具配置會被快取，加速載入
- **並行執行**：支援多個工具並行執行
- **懶載入**：工具按需載入，減少初始載入時間

### 核心價值

1. **降低技術門檻**：不需要深入了解每個資料庫的 API，AI 會自動處理
2. **提高研究效率**：自動化資料查詢與分析，節省大量時間
3. **確保資料準確性**：使用真實的科學資料庫，而非僅憑 AI 記憶
4. **促進跨領域研究**：整合多種資料來源，發現新的關聯

### 適用對象

- **研究人員**：需要快速查詢資料與進行初步分析
- **製藥公司**：需要加速藥物發現流程
- **學術機構**：需要整合多種研究工具
- **AI 開發者**：需要為 AI 系統添加科學研究能力

### 未來發展

ToolUniverse 持續擴展工具生態系統，並改善 AI 與工具的互動方式。隨著更多工具的加入與技術的進步，ToolUniverse 將成為科學研究中不可或缺的基礎設施。
